# Product

## Register

product

## Users

AirShare serves Android users who want to move photos and videos to a computer without a cable, account, cloud upload, or desktop client. They use the phone and computer on the same trusted Wi-Fi network and expect the transfer workflow to be understandable at a glance, including when permissions or connectivity are unavailable.

## Product Purpose

AirShare turns an Android phone into a temporary local web server. After the user grants media access and starts sharing, any browser on the same Wi-Fi network can browse thumbnails and download original photos or videos. Success means the user can go from opening the app to downloading a file in under a minute while their media remains on the local network.

## Brand Personality

Fast, reassuring, and direct. AirShare should feel like a dependable native utility: calm enough to trust with personal media, explicit about what is being shared, and concise without becoming cryptic.

## Anti-references

Do not resemble ad-heavy file-transfer utilities, neon hacker dashboards, glassmorphism showcases, or setup wizards that hide basic network state behind technical language. Avoid decorative gradients, ambiguous start/stop controls, surprise background sharing, and screens crowded with equal-weight cards.

## Design Principles

1. **Make sharing state unmistakable.** Stopped, starting, active, and failed states must look and read differently.
2. **Keep personal media local by default.** Explain permissions and network exposure before sharing; never imply a cloud upload.
3. **Put the next action first.** Each state should have one obvious primary action and only the supporting detail needed to complete it.
4. **Reveal technical detail progressively.** Show a friendly QR code and URL first; keep addresses, ports, and troubleshooting available without dominating the workflow.
5. **Use one language across phone and browser.** Status, terminology, localization, and visual identity should stay consistent on both surfaces.

## Accessibility & Inclusion

Meet WCAG 2.2 AA contrast intent and Android accessibility guidance. Support system font scaling, TalkBack semantics, 48 dp minimum touch targets, visible focus, reduced motion, and state communication that never relies on color alone. Ship Traditional Chinese, English, and Japanese with layouts that tolerate text expansion. Permission-denied and limited-access states must include a clear recovery path.
